# 公众号长文拟人化工作流

## 目标

长文的真人感主要来自叙事顺序、现场信息和段落呼吸，不来自口头禅密度。保留文章的证据结构，同时允许章节内部重新分段和补充自然过渡。

## 开头

优先回答四件事：

1. 作者为什么会关注或使用它；
2. 这件事与作者日常工作有什么关系；
3. 这次拿什么真实任务验证；
4. 读者接下来会看到什么。

开头不要直接摆网址、功能清单或品牌结论。网址前需要一句自然交代；首句如果是明确个人感受，可以独立成段。

素材已经说明作者与产品长期、高频共事时，可以先写这层关系，再进入产品变化。关系表达要具体但不能凭空升级：用户已经把工具称为「最佳 CP」可以保留，只有「偶尔试用」时不能自行写成长期搭档。

强烈落差出现后，可以用一句很短的即时反应制造停顿，再进入截图或数据。短句应来自真实体感，不为每个数字机械配一句「太夸张了」。

避免机械的「这次我没有……而是……」。需要对比时，先把真实行动说清楚，例如「这次我并没有刻意找一个精美 Demo，我把正在做的项目直接拿来实测」。

## 章节入口

标题后的第一段承担过渡，不要把上一章总结换个说法直接搬过来。

可以选择：

- 个人感受：「在看具体案例之前，我还是想先说一下整体感受。」
- 现实背景：「大家都知道，我最近做直播比较多。」
- 范围扩展：「说实话，能用的场景肯定不止这几个。」
- 任务来历：「这周我们还有一个客户项目。」

这些只是动作示例，不是固定句库。连续章节不要使用同一种开头。

## 案例

案例使用柔性路径：

```text
真实背景
→ 已有材料或限制
→ 使用的 Skill / 功能
→ 结果与证据图
→ 编辑、交付或失败边界
→ 对相似工作场景的判断
```

不要求每个案例机械写满六步，但必须让读者知道「为什么做、给了什么、得到了什么、是否能用」。

证据图前说明读者将看到什么；最后一张图后不要突然结束。必要时补一段：这个案例为什么典型、适合什么场景、节省了哪一步，或仍有哪些工作需要人完成。

允许使用「参考下图」「下图可以看到」这样的口述指图句，但下一句必须区分：图片直接显示的事实、作者基于图片的判断、图片无法单独证明的部分。真人感不能以牺牲证据边界为代价。

## 段落节奏

- 一句个人感受可以独立成段；
- 背景、操作、结果和判断通常不要塞进同一段；
- 连续三个段落句数、长度和起手式相近时，至少调整一处；
- 抽象判断前后插入具体动作或现场画面；
- 不为了排版把所有段落切成一句话，也不保留超过 180 个汉字的墙式段落。

## 收尾

产品体验长文可以沿着以下逻辑收束：

```text
使用场景不止本文案例
→ 工作中的完成度标准
→ 产品为何能做到或仍欠缺什么
→ 作者基于实测的判断
→ 必要的开放信息、Slogan 或行动建议
```

这是逻辑路径，不是固定模板。结尾要从正文自然长出来，避免突然出现官网、口号或「综上所述」。

如果用户已经写出一句长期判断、口头禅或 Slogan，优先把它作为最后的个人落点并逐字保留。没有用户样本时，不要为了「有金句」临时制造宏大口号。

## 商业 Brief 的自然化

Brief 决定必须覆盖的事实，不决定作者必须照着 Brief 的顺序说话。

- 不提约稿、商单、客户要求或「Brief 规定」；
- 产品能力要落到真实案例和个人判断里；
- 官方开放信息和网址放在自然过渡后；
- 不能为了自然化删掉必须披露的事实，也不能把宣传口径冒充个人实测结论。
